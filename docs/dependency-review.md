Both npm projects and the root Cargo workspace lockfile were refreshed from the
package registries. Direct dependency ranges now start at the reviewed versions.

## Selected versions

- Desktop and marketing: Nuxt 4.6.0, Vue 3.5.43, Vue Router 5.3.1 (the version
  used by Nuxt 4.6), and Tailwind CSS 4.3.3.
- Desktop: stable Nuxt UI 4.11.3, Tauri API/CLI 2.12.1, and current Tauri 2 plugins.
- Tooling: Vitest 5.0.3, Vue Vite plugin 6.0.9, jsdom 30.1.2, ESLint 10.12.0,
  Antfu ESLint config 9.5.1, and vue-tsc 3.3.12.
- Marketing: PrimeVue and its Nuxt module 4.5.5. Replaced deprecated
  `@primevue/themes` with its PrimeVue 4-compatible dependency,
  `@primeuix/themes` 2.0.3, preserving the Lara preset.
- Rust: Tauri 2.12.1, tauri-build 2.7.1, reqwest 0.13.5, httpmock 0.8.3,
  and current compatible Serde, Tokio, log, and plugin releases.

PrimeVue 5 and TypeScript 7 are deferred major migrations; this update retains
PrimeVue 4 and TypeScript 5.9.3. Node typings target the minimum supported Node
release line (22). Both npm manifests use Nuxt's Node engine requirement:
`^22.22.3 || ^24.15.0 || >=26.0.0`.

Removed unused direct dependencies `axios`, `dotenv`, `node-fetch`,
`@actions/github`, and the unrelated `eslint-config-next`. Marketing now declares
the Tailwind/PostCSS/Autoprefixer packages its configuration uses directly.

## Compatibility changes

- Desktop installs run `nuxt prepare`; the new `typecheck` script uses an explicit
  vue-tsc dependency. The existing TypeScript configuration includes generated
  Nuxt module types.
- Nuxt UI colors use semantic names, and the password input uses the current
  trailing slot styling API. The upload timestamp type reflects both persisted
  strings and in-memory Dayjs values.
- Two single-pattern Rust matches became `if let` to satisfy current Clippy.
- The broad Rust `reqwest = "0"` and `log = "0"` requirements now constrain
  updates to their reviewed minor release lines. Reqwest 0.13 uses Rustls with
  platform certificate verification by default instead of the previous native
  TLS default. Upload JSON, SOCKS support, and system proxy support are retained.
- Committed Tauri capability schemas were regenerated by the new toolchain;
  application capability declarations and CSP were not edited.

## Tauri 2.12 features

Reviewed the [Tauri 2.12 announcement](https://v2.tauri.app/blog/tauri-2.12/)
and adopted the two features relevant to this desktop app:

- The application-wide `on_permission_request` handler denies new browser
  permission requests unrelated to syncing. Notifications return `Default` to
  retain the existing consent flow. This covers requests forwarded by each
  platform's webview; previously persisted browser decisions may bypass it.
  Native Tauri capabilities are separate and unchanged.
- Updater checks and installations close their Rust resource with explicit
  `try`/`finally` (not `await using`, which Vite dev serves untranspiled and
  older webviews cannot parse) on success and failure, before relaunch. Polling waits for the prior
  check to finish and stops on unmount; late listeners and results are cleaned up.
- A blocking external script defines `Symbol.asyncDispose` before app modules
  load on older webviews. TypeScript includes `ESNext.Disposable`, and Vite
  targets ES2022 to compile the new syntax. The production HTML ordering was
  verified after generating assets.
- The crate declares Rust 1.90 as required by Tauri 2.12. Windows targets remain
  Windows 10/11; the announcement's Windows 7 and Android changes require no
  app-specific migration.

## Validation results

Validated locally with Node 22.22.3 and Rust 1.97.1 on macOS:

```sh
npm ci --include=dev --prefix apps/desktop
npm ci --include=dev --prefix marketing
npm run typecheck --prefix apps/desktop
npm run test:unit --prefix apps/desktop
npm run generate --prefix marketing
cargo fmt --all -- --check
cargo check --locked --manifest-path apps/desktop/src-tauri/Cargo.toml
cargo clippy --locked --all-targets --manifest-path apps/desktop/src-tauri/Cargo.toml -- -D warnings
cargo test --locked --manifest-path apps/desktop/src-tauri/Cargo.toml
npm run tauri:build --prefix apps/desktop -- --no-bundle
```

The desktop build generates frontend assets before compiling the release binary.
For standalone Cargo checks on a fresh checkout, run desktop `generate` first.
There are 12 JavaScript tests and four Rust tests, covering resource cleanup,
older-webview symbols, permission decisions, and upload API failure handling.
The polyfill test runs in Node because it reads a local file and uses VM contexts;
the composable tests continue to run in jsdom. The generated marketing home and Windows download pages were checked
in the browser. Native desktop E2E tests are not configured; Windows/Linux builds,
live uploads, installers, and signing were not verified locally.

## Outstanding findings

- ESLint cannot load the pre-existing config: it imports
  `.nuxt/eslint.config.mjs`, but the repository does not install/configure
  `@nuxt/eslint` to generate it. No lint script or native E2E script is defined.
- Final npm audits report 17 affected desktop packages (5 low, 8 high, 4 critical)
  and 15 affected marketing packages (11 high, 4 critical). Counts include
  transitive parent packages, not just distinct advisories. Main chains include
  Nuxt DevTools → simple-git, Nitro → listhen → node-forge, and globbing packages.
  The marketing PrimeVue module also retains an older component auto-import
  toolchain. These advisories remain even after compatible transitive updates.
- A scoped simple-git 4.0.2 override was tested and removed: Nuxt DevTools 3.4.2
  imports a default export that simple-git 4 no longer provides. npm's suggested
  Nuxt 3.7.4 downgrade was not applied. Fixing these findings requires compatible
  upstream releases or a separately tested migration; this is not an audit-clean
  dependency tree.
- RustSec auditing was not run; cargo-audit is not installed. Successful Cargo
  checks and tests do not constitute a Rust security audit.
